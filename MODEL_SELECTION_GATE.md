# Model Selection Gate

Use stable routing principles before substantial AI-assisted work. The visible picker and current
official documentation override any repository observation.

## Model Selection Brief

- Task, expected output, repository, and current surface
- Task type and risk
- Context size and change scope
- Required tool access
- Architecture and verification needs
- Latency/cost tradeoff
- Primary and fallback execution surface
- Escalation trigger

## Routing principles

- Never invent a model name or treat an old example as current authority.
- Use the fastest suitable visible option for routine, low-risk work.
- Use stronger reasoning for broad diagnosis, architecture, security, or high uncertainty.
- Match the surface to required context and tool access.
- Plan or audit first for deployment, credentials, billing, destructive operations, or data loss.
- Escalate when scope changes materially, evidence is missing, verification fails repeatedly, or
  the agent begins guessing.

## Current observations

Store only user-confirmed or runtime-observed choices in `.starter-kit/model-registry.json`.
Every entry needs its source, verification date, approved use, limitations, and stale-after date.
Expired entries require re-verification. Run evidence records what was actually used.
